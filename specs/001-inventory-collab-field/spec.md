# Feature Specification: 재물조사 다중 사용자 협업 및 현장 효율화

**Feature Branch**: `001-inventory-collab-field`

**Created**: 2025-07-30

**Status**: Draft

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 여러 부서가 동시에 조사하고 중앙에서 통합 현황 확인 (Priority: P1)

조사 담당자(각 부서)는 자신의 단말기에서 재물조사를 진행하고, 관리자는 별도 화면에서 전체 부서의 진행 현황(조사 건수, 완료율, 이상 건수)을 실시간으로 확인할 수 있다.
조사 데이터는 별도 로컬 서버 DB(SQLite 또는 JSON 파일 기반)에 저장되며, Supabase 없이도 사내 네트워크 안에서 동작한다.

**Why this priority**: 현장에서 여러 명이 동시에 조사할 때 서로 중복 조사하거나 누락하는 문제가 발생한다. 실시간 현황 공유가 가장 긴급한 업무 문제이다.

**Independent Test**: 두 개의 브라우저 탭(또는 기기)에서 각각 다른 자산을 조사하면, 두 탭 모두 상대방의 조사 결과가 수 초 내에 반영되는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 동일 세션에 두 명의 조사자가 접속한 상태에서, **When** 조사자 A가 자산 `QL-0001`을 저장하면, **Then** 조사자 B의 화면에서 5초 이내에 `QL-0001`이 조사 내역에 나타난다.
2. **Given** 관리자가 통합 현황 화면을 열어 놓은 상태에서, **When** 임의의 조사자가 자산을 저장하면, **Then** 관리자 화면의 부서별 진행률이 자동으로 갱신된다.
3. **Given** 서버가 일시적으로 응답하지 않는 상태에서, **When** 조사자가 자산을 저장하면, **Then** 로컬에 임시 저장되고 서버 복구 후 자동으로 동기화된다.

### User Story 2 — 엑셀 마스터 파일을 직접 업로드해서 자산 데이터셋 추가/갱신 (Priority: P2)

관리자는 기존 `/datasets` 고정 JSON에 의존하지 않고, 부서별 엑셀 파일(.xlsx)을 직접 업로드하여 자산 마스터를 등록하거나 갱신할 수 있다.
업로드된 데이터는 서버 DB에 저장되고 모든 접속 기기에서 즉시 사용 가능하다.

**Why this priority**: 연도마다 자산 목록이 바뀌는데 코드 수정·배포 없이 관리자가 직접 마스터를 업데이트할 수 있어야 운영이 가능하다.

**Independent Test**: 관리자가 새 엑셀 파일을 업로드하면, 다른 기기의 조사자가 앱을 새로고침하지 않고도 새 데이터셋을 선택할 수 있다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인한 상태에서, **When** 자산 목록 엑셀 파일(.xlsx)을 업로드하면, **Then** 파일이 서버에 저장되고 전체 조사자 화면에 새 데이터셋 선택지가 나타난다.
2. **Given** 업로드 도중 네트워크가 끊기면, **Then** 오류 메시지가 표시되고 이전 데이터셋은 그대로 유지된다.
3. **Given** 열(컬럼) 구조가 다른 엑셀을 업로드하면, **Then** 오류 메시지로 필수 컬럼 목록을 안내한다.

---

### User Story 3 — 관리자 통합 현황 대시보드 및 리포트 내보내기 (Priority: P3)

관리자는 전체 세션의 부서별·연도별 조사 통계(조사 건수, 완료율, 이상 건수, 미조회 건수)를 한 화면에서 볼 수 있고, 통계 결과를 엑셀 파일로 내보낼 수 있다.

**Why this priority**: 경영층 보고 및 감사 자료로 활용되므로 중요하지만, 조사 자체가 먼저 동작해야 의미 있다.

**Independent Test**: 여러 세션의 조사 결과가 있을 때, 관리자 대시보드에서 부서별 완료율 표와 전체 이상 건수가 정확히 집계되고 엑셀 파일로 다운로드된다.

**Acceptance Scenarios**:

1. **Given** 여러 부서에서 조사가 완료된 상태에서, **When** 관리자가 대시보드를 열면, **Then** 부서별 조사 건수·확인율·이상 건수가 표로 표시된다.
2. **Given** 대시보드 화면에서, **When** "통계 내보내기" 버튼을 클릭하면, **Then** 부서별 집계가 포함된 .xlsx 파일이 다운로드된다.

---

### User Story 4 — QR 연속 스캔 모드 및 원터치 확인 (Priority: P4)

현장 조사자는 자산마다 화면을 조작하지 않고, QR을 스캔하면 정상 자산이 즉시 저장("원터치 확인")되는 연속 스캔 모드를 사용할 수 있다. 이상 자산만 별도 입력 화면으로 이동한다.

**Why this priority**: 조사 건수가 많을 때 건별 저장 클릭이 가장 큰 병목이다. 연속 스캔으로 현장 조사 시간을 대폭 줄일 수 있다.

**Independent Test**: 연속 스캔 모드를 켠 상태에서 QR을 스캔하면, 자동으로 '정상' 상태로 즉시 저장되고 다음 스캔 대기 상태로 돌아간다.

**Acceptance Scenarios**:

1. **Given** 연속 스캔 모드가 활성화된 상태에서, **When** 마스터에 있는 자산의 QR을 스캔하면, **Then** 이상유무='정상', 확인여부='확인'으로 즉시 저장되고 스캔 화면이 유지된다.
2. **Given** 연속 스캔 모드에서, **When** 마스터에 없는 자산(미조회)의 QR을 스캔하면, **Then** 알림이 표시되고 수동 입력 화면으로 이동한다.
3. **Given** 이미 조사한 자산을 다시 스캔하면, **Then** 이미 조사된 자산임을 알리고 수정 여부를 묻는다.

---

### Edge Cases

- 서버가 오프라인일 때 조사 데이터는 로컬(IndexedDB)에 저장되고, 서버 복구 후 자동 재시도된다.
- 두 조사자가 동일한 자산을 동시에 저장하면 마지막 저장이 우선(Last Write Wins)되고, 충돌 발생 사실을 조사자에게 알린다.
- 엑셀 업로드 시 자산번호가 중복되면 최신 행으로 덮어쓴다.
- 네트워크 연결 없이 앱을 열면 마지막으로 캐시된 데이터셋으로 조사를 진행할 수 있다.
- 모바일 브라우저에서 카메라 권한이 없으면 수동 입력 모드만 제공된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 조사 세션의 결과를 사내 로컬 서버(별도 Supabase 없음)의 DB에 저장해야 한다.
- **FR-002**: 동일 세션에 여러 기기가 접속하면, 어느 기기에서든 새 조사 결과가 저장될 때 다른 기기에 5초 이내에 반영되어야 한다.
- **FR-003**: 관리자는 엑셀 파일(.xlsx)을 업로드하여 자산 마스터 데이터셋을 추가하거나 갱신할 수 있어야 한다.
- **FR-004**: 업로드된 자산 마스터는 서버에 저장되어 모든 접속 기기에서 즉시 사용 가능해야 한다.
- **FR-005**: 관리자는 전체 세션의 부서별·연도별 조사 통계를 화면에서 확인하고 엑셀로 내보낼 수 있어야 한다.
- **FR-006**: 조사자는 연속 스캔 모드를 켜고 끌 수 있어야 한다.
- **FR-007**: 연속 스캔 모드에서 마스터 조회 성공 자산은 자동으로 '정상' 상태로 즉시 저장되어야 한다.
- **FR-008**: 연속 스캔 모드에서 마스터 미조회 자산은 수동 입력 화면으로 이동해야 한다.
- **FR-009**: 서버가 응답하지 않을 때 조사 결과는 로컬(IndexedDB)에 임시 저장되고, 서버 복구 후 자동으로 동기화되어야 한다.
- **FR-010**: 기존 IndexedDB 기반 로컬 동작은 서버 연결 없이도 유지되어야 한다(하위 호환).

### Key Entities

- **SurveySession**: 조사 세션 (세션명, 데이터셋 ID, 부서, 생성자, 생성일, 결과 목록, 완료 여부)
- **SurveyResult**: 자산별 조사 결과 (자산번호, 자산명, 상태, 확인자, 조사일, 사진 여부 등)
- **AssetDataset**: 자산 마스터 데이터셋 메타 (ID, 이름, 상위부서, 자산 수, 업로드일)
- **Asset**: 개별 자산 레코드 (자산번호, 자산명, 모델, 규격, 설치부서, 설치장소 등)
- **SyncQueue**: 오프라인 시 로컬에 쌓인 미전송 조사 결과 큐

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 동일 세션에서 조사자 A가 저장한 결과가 조사자 B 화면에 5초 이내에 반영된다.
- **SC-002**: 관리자가 엑셀 업로드 후 30초 이내에 다른 기기에서 새 데이터셋을 선택할 수 있다.
- **SC-003**: 연속 스캔 모드에서 마스터 조회 자산 1건 처리(스캔→저장) 시간이 3초 이내다.
- **SC-004**: 서버 오프라인 상태에서도 로컬 조사 기능이 100% 동작하며, 서버 복구 후 5분 이내에 데이터가 동기화된다.
- **SC-005**: 통계 대시보드에서 100건 이상의 조사 결과가 있을 때 페이지 로딩이 3초 이내다.

## Assumptions

- 서버는 사내 네트워크에서만 접근 가능한 Node.js 기반 경량 서버(Express + SQLite 또는 파일 DB)로 구축한다.
- 클라이언트-서버 실시간 동기화는 HTTP 폴링(5초 간격) 또는 Server-Sent Events(SSE)를 사용하며, WebSocket은 1단계에서 제외한다.
- 기존 IndexedDB 기반 로컬 저장은 그대로 유지하고, 서버는 추가 동기화 레이어로 동작한다.
- 엑셀 업로드는 관리자 권한 사용자만 가능하다.
- 모바일 브라우저 지원 범위는 Chrome/Safari(iOS 15+, Android 10+)이다.
- 사진 데이터는 서버 동기화 범위에서 제외하며, 로컬 IndexedDB에만 저장된다(데이터 크기 문제).
