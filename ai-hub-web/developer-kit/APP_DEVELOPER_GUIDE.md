# EBS AI Hub 앱 개발 및 등록 가이드

이 문서는 외부 개발자가 EBS AI Hub 마켓플레이스에 제출할 브라우저 앱을 만드는 방법을 설명합니다. 앱 등록은 즉시 공개를 뜻하지 않습니다. 제출된 각 버전은 관리자 심사를 통과해야 배포됩니다.

## 1. 현재 등록할 수 있는 앱

현재 가져오기 파이프라인은 **호스트가 제공하는 React를 사용하는 브라우저용 JavaScript/TypeScript 앱**을 하나의 ESM 번들로 만듭니다. 앱은 독립 페이지가 아니라 AI Hub가 제공하는 앱 영역 안에 렌더링되는 `Body` 컴포넌트를 반환해야 합니다.

현재 방식으로 직접 패키징할 수 없는 유형은 Python·데스크톱·백엔드 프로그램, 자체 서버가 필요한 앱, 별도 페이지 전체를 마운트하는 웹사이트입니다. 이런 앱은 별도 서비스 배포와 서버 연동 계약이 필요합니다. 서버 API 연동 계약은 이 문서에서 임의로 정의하지 않습니다.

## 2. 빠른 시작

외부 개발자는 AI Hub 저장소를 복제하지 않아도 됩니다. [스타터 프로젝트](starter/) 또는 Hub의 공개 개발자 자료실에서 제공하는 ZIP을 내려받으세요. 최소 구현은 `starter/`에서 확인할 수 있습니다.

앱 폴더는 다음처럼 구성합니다.

```text
my-app/
├── aihub-app.json
└── app.js
```

### 매니페스트 `aihub-app.json`

```json
{
  "id": "my-first-app",
  "name": "내 첫 앱",
  "version": "1.0.0",
  "category": "생산성",
  "description": "앱이 해결하는 일을 한두 문장으로 설명합니다.",
  "icon": "extension",
  "entry": "app.js",
  "permissions": [],
  "author": "개발자 이름",
  "license": "MIT",
  "sourceUrl": "https://example.com/project"
}
```

필수 필드는 `id`, `name`, `version`, `category`, `entry`, `permissions`입니다.

| 필드 | 규칙 |
| --- | --- |
| `id` | 전역 고유 식별자. 영문 소문자로 시작하며 소문자·숫자·하이픈만 사용합니다. 2~64자입니다. 예: `my-first-app` |
| `name` | 사용자에게 표시할 앱 이름 |
| `version` | 1~32자의 버전 문자열. 새 릴리스마다 올리세요. 예: `1.0.1` |
| `category` | `생산성`, `운영`, `AI` 중 하나 |
| `entry` | 앱 팩토리를 내보내는 진입 파일의 상대 경로 |
| `permissions` | 아래 허용 목록에서 꼭 필요한 권한만 선언한 배열 |
| `description`, `icon`, `author`, `license`, `sourceUrl` | 선택 정보. 제출 화면의 앱 정보로 사용됩니다. |

### 앱 진입 파일

진입 파일은 기본 내보내기로 앱 팩토리를 제공해야 합니다. 팩토리는 호스트가 전달한 `React`를 사용하고 `Body` 컴포넌트를 반환합니다. 앱은 `isAdmin`, `maximized`, `toggleMaximize`, `remove`를 `Body` 속성으로 받을 수 있습니다.

```js
export default function createApp({ React }) {
  return {
    Body: function Body() {
      const [count, setCount] = React.useState(0)
      return React.createElement(
        'button',
        { onClick: () => setCount((value) => value + 1) },
        `클릭 횟수: ${count}`,
      )
    },
  }
}
```

현재 Hub는 원격 앱의 기본 타일 크기를 `4 × 3`으로 지정하며, 앱 코드의 `defaultSize` 값은 반영하지 않습니다. 앱 메타데이터는 매니페스트를 기준으로 하므로 매니페스트와 다른 앱 ID나 이름을 코드에 중복 선언하지 마세요. JSX 변환 설정을 실행하지 않으므로 예제처럼 `React.createElement`를 사용하거나 JSX를 미리 일반 JavaScript로 변환하세요. React를 앱 코드에서 별도로 import하지 마세요.

## 3. 번들·파일 제한

- 외부 개발자 스타터는 `app.js` 한 파일을 그대로 패키징하므로 `import`를 사용할 수 없습니다. 사용하는 코드와 라이브러리를 이 파일 안에 작성해야 합니다.
- 저장소 내부의 관리자용 `import_program` 파이프라인은 앱 폴더 내부의 정적 로컬 import를 합칠 수 있습니다. 외부 개발자 스타터의 기능은 아니며 외부·동적 import는 지원하지 않습니다.
- 패키지는 2MB 이하여야 합니다. CSS 파일, 이미지 등의 별도 출력 파일은 만들 수 없습니다. 필요한 스타일은 컴포넌트 안에 지정하고 작은 이미지는 데이터 URI 등으로 포함하세요.
- 패키징은 앱의 npm install, 빌드 스크립트, Vite/PostCSS 설정을 실행하지 않습니다. 소스에 필요한 도구 체인을 미리 준비해야 합니다.
- `.env`, 키 파일 등 비밀 설정 파일을 번들에 포함할 수 없습니다. 소스 코드에 직접 쓴 비밀값은 자동으로 모두 찾아내지 못하므로 제출 전에 직접 검사하세요.

## 4. 권한과 실행 경계

필요한 권한만 `permissions`에 선언하세요. 현재 패키저가 허용하는 값은 다음과 같습니다.

| 권한 | 의미와 제한 |
| --- | --- |
| `network` | 샌드박스에서 HTTPS 연결을 허용합니다. 임의 HTTP 연결은 허용되지 않습니다. |
| `storage` | 앱별·사용자별 저장 공간을 요청합니다. 저장량은 64KB, 항목 수는 100개로 제한됩니다. |
| `clipboard` | 선언 가능한 권한입니다. 실제 사용 가능 범위는 브라우저와 실행 환경의 제한을 받으며, 권한 선언만으로 모든 브라우저 기능이 보장되지는 않습니다. |
| `hub-api` | 선언 가능한 권한입니다. Hub 인증 토큰이나 임의의 허브 API 접근을 부여하지 않습니다. 별도 서버 계약 없이 호출할 수 있다고 가정하지 마세요. |
| `ai` | 선언 가능한 권한입니다. AI 호출 자격 증명이나 AI API가 앱에 자동 제공되지 않습니다. 별도 서버 연동 계약이 필요합니다. |

앱은 sandbox iframe에서 실행되며 Hub 로그인 토큰, 사용자 세션, Hub 문서와 저장소가 앱에 전달되지 않습니다. 샌드박스는 OS 수준의 자원 격리나 무제한 실행 보장을 뜻하지 않습니다. 앱에서 공통 로그인, OAuth, Google Drive, API 키 같은 공용 설정을 직접 관리하지 말고 AI Hub의 승인된 서버 계약을 사용해야 합니다. 비밀값을 프런트엔드 번들에 넣지 마세요.

## 5. 외부 개발자의 패키징·미리보기·제출

1. 개발자 킷 ZIP을 내려받아 압축을 풀고 `starter/`를 독립 프로젝트로 엽니다. Node.js 18 이상을 설치합니다.
2. `aihub-app.json`에서 앱의 고유 ID와 이름, 버전, 설명을 정하고 `app.js`를 수정합니다. 이 기본 스타터는 의존성 설치 없이 실행합니다.
3. 프로젝트 폴더에서 패키지를 만듭니다.

   ```sh
   npm run package
   ```

   출력 파일은 `dist/<id>@<version>.aihubapp.json`입니다. 스타터 패키저는 메타데이터와 앱 코드를 묶고 SHA-256을 기록합니다. JSX나 별도 라이브러리를 변환·번들하지 않으므로 코드가 단일 파일이어야 합니다.

4. EBS AI Hub에 로그인하고 **내 앱 제출**의 **로컬 미리보기**에서 패키지 파일을 선택합니다. 대시보드의 앱 추가 화면에서 미리보기 앱을 실행해 확인합니다. 이 기능은 파일을 현재 브라우저에서 실행하며 서버에 제출하지 않습니다.
5. **앱 제출**을 열어 같은 패키지를 선택하고 앱 정보와 권한을 확인합니다. 심사 메모에 앱의 목적, 테스트 방법, 외부 통신, 권한 이유를 적고 **심사 요청**을 누릅니다.
6. 제출 상태와 심사 의견은 **내 앱 제출 현황**에서 확인합니다. 승인 후 마켓플레이스에 배포됩니다. 반려된 버전을 수정하면 버전을 올려 다시 제출합니다.

패키지 대신 단일 `.js` 파일도 제출 화면에서 선택할 수 있지만, 이 경우 앱 정보와 권한을 폼에 입력해야 합니다. `.aihubapp.json` 패키지를 사용하면 매니페스트에서 정보를 미리 채울 수 있습니다. 제출은 로그인 세션으로 처리되며 별도 운영 토큰을 발급받거나 소스 코드에 넣지 않습니다.

## 6. 로컬 패키징 (저장소 개발자를 위한 절차)

이 단계는 AI Hub 저장소에 접근할 수 있는 개발자나 운영자용입니다. 외부 개발자 킷의 제출 절차와 구분됩니다.

1. 앱 폴더를 저장소의 `import_program/<폴더명>/` 아래에 둡니다.
2. 매니페스트와 진입 파일을 작성합니다.
3. 검사와 패키징을 실행합니다.

```sh
npm run import:programs -- --check
npm run import:programs
```

패키지는 `import_program/.packages/<id>@<version>.aihubapp.json`에 생성됩니다. 업로드 한도는 패키지 전체 2MB입니다. 자세한 내부 작업 절차는 [파이프라인 안내](IMPORT_PROGRAM_PIPELINE.md)를 참고하세요.

## 7. 제출과 심사

제출은 인증된 사용자가 앱 제출 화면에서 진행합니다. 제출 API는 `POST /api/apps/remote/submit`이며 로그인한 사용자의 토큰으로 인증됩니다. 저장소의 자동 제출 CLI는 내부 운영 절차이므로 외부 사용자에게 운영 토큰을 전달하지 마세요.

제출 시 앱 정보와 패키지, 심사자에게 전할 설명을 제공하세요. 설명에는 앱이 하는 일, 외부 통신 여부, 선언 권한이 필요한 이유, 테스트 방법을 포함하는 것이 좋습니다. 제출은 심사 대기 상태로 들어갑니다. 관리자가 버전별 코드를 확인해 승인해야 마켓플레이스에 배포됩니다. 승인된 버전과 다른 코드를 같은 버전으로 바꿔치기할 수 없으며, 수정 릴리스는 버전을 올려 다시 제출해야 합니다.

## 8. 제출 전 확인 목록

- [ ] 앱 ID가 고유하고 새 릴리스의 버전이 이전 버전보다 올라갔습니다.
- [ ] 매니페스트의 카테고리와 진입 파일 경로가 유효합니다.
- [ ] 앱 팩토리가 기본 내보내기이며 `Body` 컴포넌트를 반환합니다.
- [ ] Hub 토큰, 비밀번호, API 키와 개인 데이터가 코드·번들에 포함되지 않았습니다.
- [ ] 요청한 권한마다 사용 이유를 설명할 수 있습니다.
- [ ] 외부 네트워크 통신 대상과 전송 데이터를 사용자에게 설명합니다.
- [ ] 번들이 2MB 이하이고 별도 CSS·자산 파일 또는 미해결 import가 없습니다.
- [ ] 오류·빈 데이터·느린 통신 상황을 확인했고 제출한 버전을 직접 검토했습니다.

## 9. 외부 개발자 따라 하기: 만들기부터 제출까지

이 절차는 공개 개발킷으로 앱 한 개를 만들어 심사 요청하는 가장 짧은 경로입니다. Hub 저장소나 운영 토큰은 필요하지 않습니다.

1. AI Hub 마켓플레이스의 **개발자킷 다운로드**에서 ZIP을 내려받아 압축을 풉니다. 압축을 푼 `starter/` 폴더를 엽니다. Node.js 18 이상이 필요합니다.
2. `aihub-app.json`에서 `id`, `name`, `version`, `description`, `author`를 앱에 맞게 수정합니다. 앱 ID는 다른 앱과 겹치지 않게 정하고, 영문 소문자로 시작하는 영문 소문자·숫자·하이픈 2~64자만 사용합니다. 카테고리는 `생산성`, `운영`, `AI` 중 하나입니다.
3. `app.js`에서 기본 내보내기 함수와 `Body`를 수정합니다. React는 Hub가 전달하므로 import하지 않습니다. 현재 스타터의 입력·버튼 예제를 먼저 바꾸지 않고 패키징해도 됩니다.
4. 터미널을 `starter/` 폴더에서 열어 패키지를 만듭니다.

   ```sh
   npm run package
   ```

   `dist/<id>@<version>.aihubapp.json` 파일이 만들어지고 SHA-256이 기록됩니다. 이 명령은 패키지 형식과 제한을 검사하고 파일을 만들 뿐, 앱을 실행하거나 별도 의존성을 설치·번들링하지는 않습니다.
5. EBS AI Hub에 로그인하고 **마켓플레이스 → 내 앱 제출 → 로컬 미리보기**에서 방금 만든 `.aihubapp.json` 파일을 선택합니다. 대시보드에 추가된 미리보기 앱을 열어 버튼·입력·오류 상태를 직접 확인합니다. 로컬 미리보기는 현재 브라우저에서 실행되며 서버에 제출하지 않습니다.
6. 미리보기를 닫고 같은 마켓플레이스의 **앱 제출** 양식에서 패키지 파일을 선택합니다. 채워진 앱 정보와 권한을 검토하고, 심사 메모에 앱 목적·외부 통신·권한이 필요한 이유·확인 방법을 적은 뒤 **심사 요청**을 누릅니다.
7. 제출 현황에서 `심사 대기`, `승인`, `반려` 상태와 관리자 메모를 확인합니다. 심사 대기 앱은 다른 사용자에게 보이지 않습니다. 관리자는 관리자 화면의 **앱 등록**에서 제출 코드를 확인하고 승인 또는 반려합니다. 승인한 버전만 마켓플레이스에 배포됩니다.
8. 코드를 수정해 다시 제출할 때는 버전을 올립니다. 같은 앱 ID는 최초 제출자에게 귀속되며, 같은 버전을 중복 제출할 수 없습니다(반려 버전은 재제출이 허용되지만, 변경본은 새 버전으로 제출하는 것이 좋습니다).

### 패키징과 미리보기의 차이

- 패키징 명령은 파일을 검사하고 `.aihubapp.json`을 생성합니다. 개발 서버를 띄우지 않으며 앱 동작까지 검증하지 않습니다.
- 실제 실행 확인은 Hub의 **로컬 미리보기**에서 합니다. 심사 요청은 별도 단계이며, 미리보기 파일은 심사 대기열에 올라가지 않습니다.
- 스타터는 `app.js` 한 파일을 그대로 패키징합니다. npm 패키지 설치, TypeScript/JSX 변환, 여러 파일 묶기를 하지 않습니다.

## 10. 앱이 사용할 수 있는 API와 권한 계약

### 앱 런타임

외부 앱의 현재 공개 실행 규격은 아래 형태입니다.

```js
export default function createApp({ React }) {
  return {
    Body: function Body({ isAdmin, maximized, toggleMaximize, remove }) {
      return React.createElement('button', {
        onClick: toggleMaximize,
      }, maximized ? '원래 크기' : '크게 보기')
    },
  }
}
```

`Body`는 Hub가 제공한 React로 렌더링됩니다. `isAdmin`과 `maximized`는 현재 상태이며, `toggleMaximize()`와 `remove()`는 창 제어 기능입니다. 원격 앱의 기본 타일 크기는 Hub가 `4 × 3`으로 지정하며 앱의 `defaultSize` 값은 적용되지 않습니다.

### 현재 제공되는 권한

| 선언값 | 현재 동작과 제한 |
| --- | --- |
| `network` | 샌드박스에서 HTTPS 통신을 허용합니다. 외부 API가 브라우저 CORS 요청을 허용해야 하며 임의 HTTP 통신은 허용되지 않습니다. |
| `storage` | 해당 앱의 사용자별 브라우저 저장 공간을 사용합니다. 저장량은 64KB, 항목 수는 100개까지입니다. 서버 동기화나 다른 기기와의 공유는 제공하지 않습니다. |
| `hub-api` | 제출 시 선언·심사하는 권한 항목입니다. 이 선언만으로 Hub API 주소, 로그인 토큰, 사용자 데이터 접근이 제공되지는 않습니다. |
| `ai` | 제출 시 선언·심사하는 권한 항목입니다. AI 모델이나 API 키, 호출 권한이 자동으로 제공되지는 않습니다. |
| `clipboard` | 선언·심사 항목입니다. 실제 사용 가능 여부는 샌드박스와 브라우저 권한에 따라 달라지며 보장되지 않습니다. |

**외부 개발자 앱이 호출할 수 있도록 공개된 Hub 업무 API는 현재 없습니다.** Hub 계정·OAuth·Drive·사내 데이터·AI 연동이 필요하면 앱 코드에서 `/api` 경로를 직접 호출하거나 Hub 토큰을 넣지 마세요. 운영자와 별도 서버 연동 계약을 먼저 정해야 합니다. 외부 서비스 연동은 `network` 권한으로 HTTPS 요청을 할 수 있지만, 비밀 키는 브라우저 앱에 넣지 말고 개발자 측 서버에서 보관해야 합니다.

### 앱 제출·심사 API (앱 런타임용 API가 아님)

| 경로 | 인증 / 목적 |
| --- | --- |
| `POST /api/apps/remote/submit` | 로그인한 개발자가 제출하는 경로입니다. `multipart/form-data`의 파일 필드 이름은 `bundle`이며 앱 ID·이름·버전·카테고리·권한·심사 메모가 함께 전송됩니다. 성공하면 HTTP 201과 심사 대기 버전 정보가 반환됩니다. 파일은 2MB 이하여야 합니다. |
| `GET /api/apps/remote/mine` | 로그인한 제출자 자신의 제출 이력을 확인합니다. |
| `GET /api/apps/remote/submissions?status=pending` | 관리자 전용 심사 목록입니다. 상태는 `pending`, `approved`, `rejected`, `suspended`, `all`을 사용할 수 있습니다. |
| `GET /api/apps/remote/versions/:versionId/code` | 관리자 전용 코드 검토 경로입니다. |
| `POST /api/apps/remote/versions/:versionId/review` | 관리자 전용 처리 경로입니다. JSON 본문은 `{"action":"approve","note":"..."}` 또는 `{"action":"reject","note":"반려 사유"}` 형태이며, 반려 사유는 필수입니다. 승인 즉시 해당 버전이 배포 대상이 됩니다. |

웹 제출 화면이 인증과 파일 업로드를 처리하므로 외부 개발자는 이 API에 직접 토큰을 만들어 호출할 필요가 없습니다. 자동 제출 CLI나 운영 토큰은 공개하지 않습니다. 심사 API를 개발자 앱 안에서 호출해서는 안 됩니다.

## 11. 자주 만나는 제출 오류

| 응답 / 증상 | 확인할 내용 |
| --- | --- |
| 로그인 또는 401 오류 | AI Hub에 로그인한 뒤 제출 화면으로 돌아옵니다. 토큰을 코드·심사 메모에 복사하지 않습니다. |
| 400 기본 내보내기 오류 | `app.js`에 `export default function createApp(...)`가 있는지 확인합니다. |
| import 오류 또는 미리보기 실패 | `import`, 동적 import, npm 모듈, JSX 문법이 남아 있지 않은지 확인합니다. 모든 코드는 한 파일에 있어야 합니다. |
| 403 앱 ID 소유자 오류 | 기존 등록 앱과 ID가 겹치지 않는 새 ID를 사용하거나 해당 앱의 소유자 계정으로 제출합니다. |
| 409 버전 중복 | `aihub-app.json`의 버전을 올리고 다시 패키징합니다. |
| 413 용량 오류 | 생성된 패키지 파일을 2MB 이하로 줄입니다. |
| 제출 완료 후 마켓플레이스에서 보이지 않음 | 정상적인 심사 대기 상태일 수 있습니다. 제출 현황과 관리자 심사 결과를 확인합니다. |

## 범위 안내

이 가이드는 현재 AI Hub 저장소의 가져오기 파이프라인과 샌드박스에서 확인되는 계약을 설명합니다. 호스팅 서버 앱, 사용자별 OAuth/Drive 연결, 비밀값 보관, 인증된 Hub API 호출은 현재 이 브라우저 패키지 계약에 포함되지 않습니다. 해당 연동이 필요하면 AI Hub 운영자와 별도 서버 계약을 먼저 협의하세요.
