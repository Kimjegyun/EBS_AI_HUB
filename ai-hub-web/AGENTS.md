# 저장소별 개발 책임

사용자가 2026-10-17에 지정한 개발 경계를 따른다.

## AI Hub: 이 저장소

`D:\!!__AI_HUB\ai-hub-web`은 `ebs-aihub.com`의 전체 프로그램을 관리하는 플랫폼이다.

- 공통 로그인, 사용자·그룹·권한·승인 관리
- 프로그램 등록·접속·실행 연동 및 공통 게이트웨이
- 계정 연결, OAuth 설정, 공용 Drive 연결·저장소 관리 정책
- API 키 등 공통 인증 설정의 서버 보관·접근 제어와 관리자 설정 화면
- 운영 계정 정보와 공통 설정 문서

## ACAP 원격버전: 현재 개발 대상

`D:\EBS_AI_CONTENTS_CREATION_v2`는 현재 ACAP 원격버전 작업 폴더다. GitHub는 `Kimjegyun/EBS_AI_CONTENTS_CREATION_REMOTE`, 기준 브랜치는 `remote-version`이다. 이 폴더의 옛 이름이나 `origin` 이름만 보고 로컬버전으로 판단하지 않는다.

- ACAP 로고·헤더·단계별 화면 등 제작 프로그램 UI
- 프로젝트·스크립트·나레이션·디자인·BGM·이미지·영상 제작
- 프로젝트 저장·조회·내보내기, 저장폴더 보기, 로컬 폴더 선택
- AI Hub에서 제공하는 인증·설정·권한을 이용하는 제작 기능과 서버 어댑터

## ACAP 로컬버전: 별도 작업 폴더

`D:\EBS_AI_CONTENTS_CREATION_LOCAL`은 독립 Git 저장소로 분리한 로컬버전 작업 폴더다. GitHub는 `Kimjegyun/EBS_AI_CONTENTS_CREATION_v2`, 기준 브랜치는 `master`다. 개인 PC의 제작 기능·개인 연결·로컬 저장·Premiere 연동을 담당한다. 원격버전의 인증 잠금·공용 Drive 정책을 자동으로 적용하지 않는다.

## 작업 규칙

1. 변경 전에 플랫폼 관리 기능인지 ACAP 제작 기능인지 판단해 해당 저장소에서 수정한다. 현재 작업 디렉터리를 기능 소유권의 기준으로 삼지 않는다.
2. 공통 계정·Google 연결·API 키 관리 기능을 ACAP UI에 새로 추가하지 않는다. ACAP에서 관련 기능이 필요하면 AI Hub의 설정·서버 계약을 이용한다.
3. ACAP 화면 변경을 AI Hub에서 구현했다고 보고하지 않는다. 공통 설정 관리와 제작 화면의 설정 소비를 구분한다.
4. 두 저장소를 수정해야 하면 각각의 변경 목적, 연결 계약, 검증 및 배포 대상을 구분해 보고한다.
5. 기존 Google 연결·세션·사용자별 Drive 폴더와 저장 프로젝트를 보존한다. 기존 인증 정보를 복제하거나 공통 비밀값을 클라이언트에 전달하는 방식으로 경계를 나누지 않는다.
6. 현재 ACAP에 남아 있는 공통 연결·관리 기능은 현재 구현 위치와 목표 소유권을 구분한다. 문서 변경만으로 기능을 AI Hub로 이관했다고 주장하지 않는다.
7. 현재 개발 대상은 **ACAP 원격버전**이다. 사용자가 대상을 바꾸기 전까지 ACAP 기능 요청은 원격 작업 폴더에 적용한다. 공통 플랫폼 관리 기능은 AI Hub에서 수정한다. 로컬버전에는 요청 없이 기능을 복제·병합하지 않는다.
8. 세 제품은 독립 GitHub 저장소로 관리한다. 커밋·push 전에 `development-target.json`과 `scripts/verify-development-target.mjs`로 대상 저장소를 확인한다. 다른 버전으로 일괄 push하거나 이력을 강제로 맞추지 않는다.
9. `localhost`에서 원격버전의 서버 관리 화면을 열어도 로컬버전 개발로 바뀌지 않는다. 제품 구분은 Git 저장소·작업 폴더·브랜치로 판단한다.

자세한 기준과 현황은 [개발 책임 구분](docs/DEVELOPMENT_BOUNDARIES.md)을 참고한다.
GitHub 분리와 현재 작업 대상은 [개발 상태](docs/DEVELOPMENT_STATUS.md)를 참고한다.
