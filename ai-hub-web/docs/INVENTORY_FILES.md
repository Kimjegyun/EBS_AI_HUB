# 재물조사 엑셀 파일 구조 (종류별 1개)

| 파일 | 개수 | 위치 | 설명 |
|---|---|---|---|
| 서버 원본 | 1 | `server/uploads/inventory-survey/` | 현재 운영관리부 자산 마스터. 교체·삭제하면 연결 데이터와 파일을 모두 지웁니다. |
| 서버 반영본 | 저장하지 않음(항상 1벌) | `inventory_submission_assets`(DB) | 조사 결과는 본부·자산 단위로 DB에 합쳐집니다. 전사 운영관리부 파일, 본부·부서·입력자별 파일은 다운로드할 때 같은 데이터로 만듭니다(`/results/export`). 그래서 서로 항상 일치합니다. |
| 유저 원본 | 기기·사용자당 1 | IndexedDB `user-original:{사용자}` | 조사하는 본부·부서의 원본 시트입니다. 화면에는 보이지 않고, 작업사본을 새로 만들 때(처음부터 다시 조사할 때 등)만 씁니다. 다른 조사를 시작하면 교체됩니다. |
| 유저 반영본 | 기기·사용자당 1 | IndexedDB `user-report:{사용자}` | 원본에 조사 결과를 반영한 작업사본입니다. 조사부서와 조사자 이름이 들어가며, 저장할 때마다 같은 파일을 덮어씁니다. 파일 이름: `{연도}_재물조사_{본부}_{부서}_{조사자}.xlsx` |

ERP 검수 반영 파일(②)은 받을 때만 만들고 기기에 저장하지 않습니다.

## 서버 조사 결과 미리보기 (관리자)

관리자 화면의 **서버 조사 결과 엑셀 내보내기**(`PublishedSubmissionDownload.tsx`, `showPreview`)에서는 본부·조사부서·입력자를 고르면 해당 **등록 자산 목록**이 바로 아래 표로 나옵니다.

- 열: 본부, 조사부서, 입력자, 자산번호, 자산명, 설치부서, 위치, 상태, 조사일시. 최신 조사순으로 정렬합니다.
- 표 위의 검색창으로 자산번호, 자산명, 위치, 설치부서, 모델을 검색합니다. 100건씩 보여주고 **더 보기**로 이어서 봅니다.
- 검색어가 있으면 **엑셀 다운로드도 검색 결과만**(기본 켜짐)으로 표에 보이는 그대로 내보냅니다. 파일 이름에 `_검색_…`이 붙습니다.
- 일반 사용자 화면에는 지금처럼 필터와 다운로드만 보입니다.
- **입력자 성명 표시:** 입력자는 조사할 때의 이름이라 영문 ID(예: `ihjeon`)일 수 있습니다.
  - 관리자 화면에서는 **사용자 관리**의 성명과 맞춰 `홍길동 (ihjeon)`처럼 보여줍니다. 표시 이름이나 이메일 앞부분이 같은 회원을 찾습니다.
  - 입력자 선택 목록, 미리보기 표, 내려받는 엑셀의 입력자 열, 파일 이름에 모두 적용됩니다.
  - 필터는 원래 입력값으로 걸러서 결과는 바뀌지 않습니다.
  - 성명이 등록되지 않은 사람은 입력값 그대로 보입니다. 사용자 관리에서 **성명 미입력** 표시를 눌러 채우면 됩니다.

## 관리자 인증 (자산파일 목록 등 관리자 전용 기능)

자산파일 목록, 자산파일 삭제, 전사 엑셀은 서버가 **관리자 인증 코드**를 확인한 요청에만 응답합니다. 일반 현장 토큰으로 요청하면 403을 돌려줍니다.

- **문제:** 관리자 로그인 때 확인한 코드를 예전에는 탭 단위 임시 저장소(sessionStorage)에만 두었습니다. 로그인은 유지되는데 탭이나 앱을 다시 열면 코드가 사라졌습니다. 그러면 Settings의 자산파일 목록이 비어 보였습니다.
- **수정:**
  - 확인된 코드를 로그아웃할 때까지 보관합니다(`adminAccess.ts`, 포털별 localStorage). 로그아웃하면 지웁니다(`AuthContext`).
  - 그래도 인증이 없으면 Settings의 '자산파일 관리'에 **관리자 인증 코드** 입력란이 나타납니다. 코드를 넣으면 바로 목록이 표시됩니다.
  - Settings의 각 영역은 따로 불러옵니다. 한 요청이 거부돼도 나머지 화면은 그대로 보입니다.

## 전사 재물조사 엑셀 (관리자 전용)

관리자 계정의 조사 목록 화면에 **전사 재물조사 엑셀** 상자가 있습니다. 조사연도를 정하고 **전사 엑셀 다운로드**를 누르면 파일을 받습니다.

- 내용: 현재 운영관리부 원본의 **모든 본부 시트**에 서버의 확정 결과를 반영합니다. 반영하는 항목은 조사부서, 조사자, 조사일시, 확인완료이고, 마스터에 없는 자산은 별도 시트에 모읍니다. 파일 이름은 `{연도}_전사_재물조사.xlsx`입니다.
- 서버: `GET /api/inventory/submission/company-workbook?year=` (`authorize('admin')`, `buildCompanyWorkbook`)
  - 관리자 토큰이 아니면 403을 돌려줍니다.
  - 파일을 저장하지 않고 요청할 때마다 만듭니다.
- **여러 부서·여러 조사자 취합:**
  - 결과는 본부·자산 단위로 하나씩 서버에 모입니다. 같은 본부의 여러 부서와 조사자가 동시에 등록해도 한 파일에 모두 들어갑니다.
  - 같은 자산을 두 사람이 다르게 등록하면 나중 사람에게 충돌 확인 창이 뜹니다. 확인한 내용으로 저장됩니다.
- **다른 본부 자산:** 다른 본부 조사자가 자기 구역에서 찾아 등록한 자산은 그 자산이 원래 있는 본부 시트의 행에 반영됩니다.
  - 조사부서는 `기술본부 송출부`처럼 본부 이름을 붙여 표시합니다.
  - 같은 자산을 원래 본부와 다른 본부에서 모두 확인했다면 **더 최근 조사**가 반영됩니다.
  - 예전에는 이런 자산이 모두 `제출 미매칭 확인` 시트로 갔습니다. 지금 그 시트에는 어느 본부 시트에도 없는 자산만 모입니다.
- **검증:** `npx tsx scripts/test-company-workbook.ts`는 2개 본부, 3개 부서, 4명 조사자의 동시 등록, 다른 본부 자산, 미매칭 자산을 확인합니다.
- 본부별·부서별·입력자별 파일은 기존 **서버 조사 결과 엑셀 내보내기**에서 받습니다. 모두 같은 서버 결과로 만들어지므로 서로 일치합니다.

## 흐름

1. 조사자 기기에서 유저 반영본(조사부서·조사자 포함)을 갱신하고 기기에 저장합니다.
2. **최종 등록**을 누르면 엑셀 파일이 아니라 **조사 결과 데이터**를 전송합니다.
3. 서버는 부서·자산 단위로 합칩니다. 자산마다 버전이 있어서 충돌하면 알려 줍니다.
4. 전사 운영관리부 파일과 부서별·조사자별 파일은 다운로드할 때 생성됩니다.

엑셀 파일을 올려서 합치지 않는 이유는 세 가지입니다. 충돌을 판단할 수 없고, 파일이 조사자 수 × 업로드 횟수만큼 늘고, 양식이 조금만 어긋나도 칸이 밀리기 때문입니다.

## 서버 삭제를 기기에 반영

`src/apps/inventory/localCleanup.ts`의 `pruneRemovedServerData`가 조사 목록 화면을 열 때, 포커스가 돌아올 때, 데이터셋이 바뀔 때, 그리고 60초마다 실행됩니다.

- 서버 목록에도 없고 앱에 내장된 데이터셋(`DATASET_SOURCES`)도 아닌 데이터셋은 기기에서 지웁니다. 그 데이터셋의 조사, 데이터셋 캐시, 유저 원본과 반영본이 함께 지워집니다.
- 지우기 전에 **서버에 보내지 않은 확인 결과**를 백업 1개(`unsent-backup:{사용자}`)에 추가합니다. 조사 목록 위에 표시되는 **백업 엑셀 받기**로 내려받고, **삭제**로 지웁니다.
- 서버 목록을 받지 못하면(오프라인) 아무것도 지우지 않습니다.
- 예전 버전이 남긴 사본(`master-source:`, `master-workbook:`, `workbook:`)은 이때 정리됩니다.

## 서버 정리

- 원본을 삭제(`purgeMasterFile`)하면 예전 버전의 제출 파일(`dept-comparison`, `submission-*.xlsx`)도 함께 지웁니다.
- 서버가 시작할 때 `removeLegacySubmissionFiles`가 남아 있는 예전 제출 파일을 정리합니다.
