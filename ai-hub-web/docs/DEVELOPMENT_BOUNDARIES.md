세 제품은 GitHub 저장소도 각각 구분한다. 실제 주소·브랜치와 현재 작업 대상은 [DEVELOPMENT_STATUS.md](DEVELOPMENT_STATUS.md)에 기록한다. 아래 표의 ACAP 기능은 현재 요청에 따라 원격버전에 적용하며, 로컬버전에는 자동 전파하지 않는다.

## 기능별 소유권

| 기능 | 담당 |
| --- | --- |
| 사용자 가입·로그인, USER·ADMIN, 사용자 그룹·승인 | AI Hub |
| 프로그램 목록·등록·접속 권한·공통 진입 경로 | AI Hub |
| 원격 서비스의 Google Cloud OAuth 설정, 저장용 Google 계정 연결 | AI Hub |
| 공용 Drive 활성화·재연결, 공통 저장소 정책 | AI Hub |
| 공통 API 키 등록·보관·잠금·연결 상태 관리 | AI Hub |
| ACAP 로고·헤더·제작 단계와 설정을 표시하는 화면 | ACAP |
| 스크립트·나레이션·이미지·영상 제작 | ACAP |
| 제작 프로젝트 저장·조회·불러오기·내보내기 | ACAP |
| 구글 드라이브 저장폴더 보기·로컬저장 폴더 선택 | ACAP |
| 관리자가 제공한 인증·권한을 이용하는 제작 API·저장소 어댑터 | ACAP, AI Hub와의 계약에 따라 구현 |

여기서 UI의 위치는 그 기능의 책임을 따른다. 전체 프로그램의 연결·인증을 관리하는 UI는 AI Hub, ACAP에서 결과물을 만들고 확인하는 UI는 ACAP에 둔다. ACAP 내부의 제작 옵션과 AI Hub의 공통 계정 설정을 같은 종류의 설정으로 취급하지 않는다.

## 현재 구현과 목표 구조의 차이

- 사용자·권한 관리와 공통 포털은 AI Hub에 있다.
- 로고, 헤더의 저장폴더 버튼, 파일 탐색·저장 UI는 ACAP에 적용되어 있다. 이는 ACAP 화면 변경이다.
- Google 연결, OAuth JSON 가져오기, 공용 Drive 활성화 UI와 해당 서버 처리는 현재 ACAP에도 존재한다. 이 부분의 관리 책임은 위 기준상 AI Hub이며, 아직 실행 코드를 AI Hub로 이관한 상태는 아니다.
- 현재의 로컬 ACAP 설정 절차는 기존 구현을 사용하는 운영 절차다. 향후 공통 설정을 계속 ACAP에 추가하라는 개발 기준이 아니다.
- 원격 USER·ADMIN의 인증·API 설정 제한은 유지한다. 관리 위치를 옮긴다는 이유로 외부 계정의 비밀정보 열람 권한을 풀지 않는다.

공통 연결 기능의 실제 이관에는 기존 OAuth 연결·서버 세션·Drive 폴더와 프로젝트를 보존하는 이전 처리, AI Hub와 ACAP 사이의 서버 인증 계약, 각 저장소의 검증과 배포가 필요하다. 이번 경계 문서화만으로 이관 완료를 의미하지 않는다.

## 변경 및 보고 기준

작업을 시작할 때 기능 소유권을 먼저 확인하고, 변경한 저장소·기능·검증·배포 결과를 각각 설명한다. 공유 인터페이스가 바뀌는 경우에만 두 저장소를 함께 수정한다. 운영 계정 정보의 기준 문서는 AI Hub의 [ACAP_GOOGLE_ACCOUNTS.md](ACAP_GOOGLE_ACCOUNTS.md)이다. 실제 비밀번호·토큰·비밀키를 문서나 앱 간 클라이언트 설정에 기록하지 않는다.
