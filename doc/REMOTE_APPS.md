# 앱 만들기 · 제출 · 심사 — 공동 마켓플레이스

EBS AI HUB는 **허브를 다시 빌드하지 않고** 앱을 추가할 수 있습니다.
누구나 앱을 만들어 제출하고, 관리자가 승인하면 그 조직의 모든 사용자가 씁니다.

```
0. 관리자   SDK·템플릿 배포                       (한 번)
1. 개발자   템플릿으로 개발 + 로컬 미리보기
2. 개발자   빌드 → 단일 ESM 번들
3. 개발자   마켓플레이스에 제출                    status = pending
4. 관리자   코드 열람 → 승인 / 반려(사유)          status = approved | rejected
5. 사용자   승인된 버전만 내려받아 실행
6. 관리자   문제 발견 시 즉시 정지                 status = suspended
```

**승인은 앱이 아니라 «버전» 단위입니다.** 승인받은 앱을 나중에 다른 코드로
바꿔치기해도 새 버전은 다시 `pending` 이 되고, 사용자는 이전 승인 버전을 계속 받습니다.

---

## 앱을 넣는 세 가지 방법

| | 내장 앱 | **제출 앱** | 관리자 직접 등록 |
|---|---|---|---|
| 누가 | 저장소 기여자 | **누구나** | 관리자 |
| 방법 | 파일 추가 + 레지스트리 한 줄 | 마켓플레이스에서 제출 | 앱 등록 화면에서 업로드 |
| 심사 | PR 리뷰 | **관리자 승인** | 없음 (관리자가 이미 확인) |
| 빌드 필요 | 예 (허브 재빌드) | 아니오 | 아니오 |
| 배포 범위 | 이 저장소를 쓰는 모두 | 그 서버를 쓰는 조직 | 그 서버를 쓰는 조직 |

널리 쓰일 앱은 [CONTRIBUTING.md](../CONTRIBUTING.md) 대로 PR로 등록해 주세요.
조직 전용 앱은 제출 경로가 빠릅니다.

## 1. 만들기

**빌드 도구를 쓰는 방법 (권장)** — JSX·TypeScript·npm 패키지를 그대로 씁니다.

```bash
cp -r examples/app-template ~/my-app
cd ~/my-app && npm install && npm run build
```

자세한 사용법은 [`examples/app-template/README.md`](../examples/app-template/README.md).

**빌드 없이 만드는 방법** — 파일 하나에 직접 씁니다.

```js
export default ({ React }) => {
  const { useState } = React
  const h = React.createElement

  function Body(ctx) {
    const [n, setN] = useState(0)
    return h('div', { className: 'p-4' },
      h('p', null, `${ctx.isAdmin ? '관리자' : '사용자'}님 안녕하세요`),
      h('button', { onClick: () => setN(n + 1) }, `클릭 ${n}`),
    )
  }

  return {
    id: 'hello-world',
    name: '인사',
    icon: 'waving_hand',          // Material Symbols 이름
    description: '최소 예제',
    category: '생산성',            // 코어 | 생산성 | 운영 | AI
    version: '1.0.0',
    defaultSize: { w: 3, h: 3, minW: 2, minH: 2 },
    Body,
  }
}
```

전체 예제: [`examples/remote-apps/hello-world.app.js`](../examples/remote-apps/hello-world.app.js)

### 지켜야 할 것

| 규칙 | 이유 |
|---|---|
| **정적 `import` 금지** | 동적 로딩 시 해석되지 않습니다. 서버가 제출을 거부합니다. |
| **React를 번들하지 말 것** | React 인스턴스가 둘이면 훅이 깨집니다. 반드시 인자로 받은 `React`를 쓰세요. |
| 빌드 없이 쓸 땐 `React.createElement` | JSX 를 변환할 단계가 없습니다. 템플릿을 쓰면 JSX 가 됩니다. |
| 앱 id는 소문자·숫자·하이픈 | 저장 키로 쓰입니다. 내장 앱과 같은 id는 무시됩니다. |
| 번들 2MB 이하 | 서버 제한입니다. |

### 쓸 수 있는 것

- 호스트의 React 전부 — `useState`, `useEffect`, `useMemo`, `createElement` …
- 브라우저 API 전부 — `fetch`, `localStorage`, `IndexedDB` …
- 허브의 Tailwind 클래스 — `text-on-surface`, `bg-primary` 등 디자인 토큰이 그대로 먹습니다
- `Body`가 받는 `ctx` — `isAdmin`, `maximized`, `toggleMaximize` 등 (계약은 [`src/apps/types.ts`](../ai-hub-web/src/apps/types.ts))

### 팩토리 반환값

| 필드 | 필수 | 설명 |
|---|---|---|
| `Body` | ✅ | 위젯 본문 컴포넌트. `ctx`를 props로 받습니다. |
| `defaultSize` | | 대시보드 기본 크기. 생략 시 `{w:4,h:3,minW:2,minH:2}` |
| `HeaderExtra` | | 위젯 제목 줄 오른쪽 컨트롤 |
| `Provider` | | 헤더와 본문이 상태를 공유해야 할 때 |
| `bodyClassName` | | 본문 래퍼에 붙일 추가 클래스 |

`id`·`name`·`icon`·`description`·`category`·`version`은 **제출할 때 입력한 값이 우선**합니다.
목록 화면과 실제 앱이 어긋나지 않게 하기 위해서입니다.

## 2. 미리 보기

제출하기 전에 **내 화면에서만** 띄워 봅니다.

마켓플레이스 → **로컬 미리보기** → 번들 파일 선택

서버에 아무것도 올라가지 않습니다. 대시보드의 «앱 추가»에 `[미리보기]` 항목으로
나타나고, 새로고침하면 사라집니다. 나만 봅니다.

---

## 3. 제출

마켓플레이스 → **앱 제출**

번들 파일과 메타데이터, 그리고 **접근 범위**를 함께 냅니다.

| 접근 범위 | 뜻 |
|---|---|
| `network` | 외부 도메인으로 `fetch` 등을 호출 |
| `storage` | `localStorage` · `IndexedDB` 사용 |
| `hub-api` | 허브의 `/api/...` 호출 |
| `ai` | AI 게이트웨이 호출 |
| `clipboard` | 클립보드 읽기·쓰기 |

이건 권한을 «요청»하는 것이 아니라 **무엇을 하는지 미리 밝히는 것**입니다.
기술적으로 막지 않습니다 — 심사자가 코드에서 무엇을 확인할지 알려 주는 용도입니다.
선언하지 않은 접근이 코드에 있으면 심사 화면에 표시되고, 대개 반려 사유가 됩니다.

제출 결과는 «내 제출 현황»에서 봅니다. 반려되면 사유가 함께 표시됩니다.

**새 코드를 낼 때는 버전을 올리세요.** 같은 버전은 다시 제출할 수 없습니다
(반려된 버전은 예외입니다).

---

## 4. 심사 (관리자)

앱 등록 화면 → **앱 심사**

각 제출에 대해 심사자가 보는 것:

- 제출자가 남긴 설명 — 무엇을 하는 앱이고 왜 그 접근이 필요한지
- 선언한 접근 범위
- **확인이 필요한 지점** — 선언하지 않은 접근, `eval`, `document.cookie` 등
- **번들 코드 전문**
- SHA-256

> ⚠️ 자동 검사는 **우회하기 쉽습니다.** 문자열을 쪼개거나 계산해서 만들면 잡히지 않습니다.
> 안내일 뿐이고, 판단은 코드를 직접 읽고 하셔야 합니다.

**승인**하면 그 버전이 곧바로 배포됩니다.
**반려**에는 사유가 필요하며, 제출자에게 그대로 전달됩니다.

---

## 5. 배포와 정지

승인된 버전만 사용자에게 내려갑니다.

앱 등록 화면 → 원격 앱 목록 → **⏸ 정지**

정지하면 사용자 화면에서 즉시 사라집니다. **삭제와 다릅니다** — 코드와 이력이 남고
언제든 되돌릴 수 있습니다. 승인 후 문제가 드러났을 때 쓰세요.
삭제는 되돌릴 수 없고, 그 앱의 모든 버전이 사라집니다.

## 동작 원리

```
[개발자] 제출
   └→ 서버가 검증(ESM·정적 import 없음·크기·id 형식) 후
      uploads/apps/<id>@<버전>-<해시8>.js 로 저장
      remote_app_versions 에 status=pending 으로 기록
      ※ 버전마다 파일이 따로다 — 승인된 버전이 새 제출로 덮이지 않는다

[관리자] 심사
   └→ GET  /api/apps/remote/submissions          대기 목록
   └→ GET  /api/apps/remote/versions/:id/code    코드 + 확인 지점
   └→ POST /api/apps/remote/versions/:id/review  승인 / 반려
      승인 시 remote_apps.current_version_id 가 이 버전을 가리킨다

[허브] 로그인 후
   └→ GET /api/apps/remote            승인된 앱만 반환
   └→ GET /api/apps/remote/:id/bundle 승인된 배포 버전만 반환
   └→ Blob URL 로 만들어 동적 import
   └→ export default 팩토리에 호스트 React 를 넘겨 실행
   └→ 반환값을 AppPlugin 계약에 맞게 검증한 뒤 레지스트리에 등록
   └→ 마켓플레이스·대시보드·설치 관리 화면에 자동 반영
```

`import()`는 헤더를 붙일 수 없어서, 번들을 먼저 인증된 `fetch`로 받아 Blob URL로 만들어 넘깁니다.

앱 하나가 실패해도 나머지는 정상 등록되며, 실패한 앱은 **관리자 화면에 실패 사유가 표시**됩니다.

### 누가 무엇을 받을 수 있나

| 버전 상태 | 일반 사용자 | 제출자 본인 | 관리자 |
|---|---|---|---|
| `pending` | ❌ 404 | ⭕ 미리보기 | ⭕ 심사 |
| `approved` | ⭕ | ⭕ | ⭕ |
| `rejected` | ❌ | ⭕ | ⭕ |
| `suspended` | ❌ 404 | ❌ | ⭕ |

## 앱 이식 — 다른 회사 허브에 붙이기

승인되어 배포 중인 앱은 **파일 하나로 내보내** 다른 조직의 허브에 그대로 설치할 수 있습니다.

### 내보내기
관리자 화면 → 원격 앱 목록 → 앱 줄의 **⤴ 버튼** → `<앱id>-<버전>.aihubapp.json` 다운로드

파일에는 메타데이터와 번들 코드가 함께 들어 있습니다.

```json
{
  "format": "ebs-ai-hub-app",
  "formatVersion": 1,
  "exportedAt": "2026-08-25T...",
  "app": { "id": "hello-world", "name": "인사", "version": "1.2.0",
           "author": "A조직", "license": "MIT", "sourceUrl": "...",
           "permissions": ["storage"] },
  "sha256": "5800a7e5...",
  "code": "export default ({ React }) => ({ ... })"
}
```

### 가져오기
관리자 화면 → 원격 앱 → **가져오기** → 파일 선택

받는 쪽은 **메타데이터를 입력할 필요도, 빌드할 필요도 없습니다.**
관리자가 직접 가져오는 행위 자체가 승인이므로 바로 배포됩니다.
**가져오기 전에 `code` 필드를 열어 읽어 보세요.**

### 무결성 확인
내보낼 때 기록한 SHA-256 과 실제 코드의 해시를 비교합니다.
다르면 가져오기는 되지만 **경고가 표시됩니다** — 파일이 손상됐거나 중간에 바뀐 것입니다.

### 주고받을 때의 권장 사항
- 앱 소스는 GitHub 등 공개 저장소에 두고 `sourceUrl` 에 적어 주세요. 받는 쪽이 코드를 검토할 수 있습니다.
- 라이선스를 반드시 채워 주세요. 받는 쪽의 재배포 가능 여부가 여기서 갈립니다.
- 버전을 올려 내보내면 같은 id 로 덮어써집니다.

## ⚠️ 보안 — 반드시 읽어주세요

**원격 앱 코드는 허브와 같은 권한으로 브라우저에서 실행됩니다.**
로그인 세션, localStorage, 허브가 호출할 수 있는 모든 API에 접근할 수 있습니다.

| 장치 | 내용 |
|---|---|
| 제출 | 로그인한 사용자 누구나 |
| 배포 | **관리자 승인을 받은 버전만** |
| 승인 전 코드 열람 | 관리자와 제출자 본인만 |
| 버전 무결성 | 승인은 버전 단위 — 승인 후 코드를 바꿔치기할 수 없음 |
| 소유권 | 앱 id는 처음 등록한 사람만 새 버전을 낼 수 있음 |
| 접근 선언 | 제출자가 밝히고, 어긋나면 심사 화면에 표시 |
| 정지 | 승인 후에도 즉시 배포 중단 가능 (되돌릴 수 있음) |
| 무결성 | 제출 시 SHA-256 기록, 관리자 화면에서 앞 8자 확인 |
| **격리** | **없음 — 샌드박스가 아닙니다** |

격리가 없으므로 **심사가 유일한 방어선입니다.**
승인 버튼을 누르기 전에 코드를 실제로 읽으세요. 자동 검사는 참고일 뿐입니다.

향후 로드맵: iframe 샌드박스 실행, 앱 서명, 선언한 권한의 실제 강제.

## 문제가 생기면

| 증상 | 원인 |
|---|---|
| 제출 시 `정적 import 는 사용할 수 없습니다` | 파일 상단의 `import` 문을 지우고 인자로 받은 React를 쓰세요. 템플릿을 쓰면 빌드가 처리합니다. |
| 제출 시 `ESM 기본 내보내기가 없습니다` | `export default` 팩토리가 있어야 합니다 |
| 제출 시 `버전 ... 은 이미 제출되어 있습니다` | 버전을 올려서 다시 내세요. 승인은 버전 단위입니다. |
| 제출 시 `이 앱 id는 다른 사용자가 등록했습니다` | 앱 id는 처음 등록한 사람 소유입니다. 다른 id를 쓰세요. |
| 승인했는데 사용자 화면에 안 보임 | 마켓플레이스에서 사용자가 직접 «사용하기»를 눌러야 합니다. 자동 설치되지 않습니다. |
| 목록에 `불러오기 실패` | 관리자 화면에 표시된 사유를 보세요. 대개 팩토리 반환값에 `Body`가 없는 경우입니다 |
| 훅 오류(`Invalid hook call`) | React를 번들에 포함시켰습니다. 인자로 받은 React만 쓰세요 |
| 화면이 비어 있음 | `Body`가 `React.createElement` 결과를 반환하는지 확인하세요 (JSX는 빌드 없이는 변환되지 않습니다) |
