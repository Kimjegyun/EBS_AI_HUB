# 재물조사 (`inventory`)

> 자산 라벨 QR을 찍어 현물을 확인하고, 검수 결과를 ERP 본부 파일과 운영관리부 양식에 반영해 엑셀로 돌려주는 앱.

- **분류**: 운영
- **구현**: [`src/apps/inventory/`](../../ai-hub-web/src/apps/inventory/) — 허브 위젯은 [`src/apps/inventoryApp.tsx`](../../ai-hub-web/src/apps/inventoryApp.tsx), 폰 전용 PWA는 [`inventory.html`](../../ai-hub-web/inventory.html) → [`InventoryStandaloneApp.tsx`](../../ai-hub-web/src/apps/inventory/InventoryStandaloneApp.tsx)
- **권한**: 조사·검수는 전체 사용자 / DB 구성·기기 관리·통계는 관리자 전용

## 1. 개요

정기 재물조사(자산 실사)를 현장에서 폰으로 처리하는 앱입니다. 관리자가 운영관리부 배부 양식과 ERP 자산현황을 합쳐 본부별 마스터 DB를 서버에 올려두면, 현장 담당자는 폰에 설치한 PWA로 자산 QR을 찍어 장부와 현물을 대조하고 검수 정보를 남깁니다. 조사가 끝나면 두 종류의 엑셀 산출물이 서버에 보관되고 기기에도 저장됩니다.

허브 안의 위젯으로도 열리지만, 현장에서는 **독립 PWA(`/inventory.html`)** 로 쓰는 것이 기본입니다. PWA는 로그인 없이 동작하고, 네트워크가 끊겨도 이미 받아둔 데이터로 계속 조사할 수 있습니다.

## 2. 실행 순서

### A. 관리자 준비 (본부당 1회)

데이터셋 등록·삭제는 **`설정` 탭 → DB 파일 관리**에서만 합니다. (`데이터셋` 탭은 확인 전용입니다)

1. 허브에서 **재물조사 앱 → `설정` 탭**을 엽니다. (관리자에게만 보입니다)
2. **① 운영관리부 전사 자산 현황 : 엑셀** 을 올립니다. 전사 본부별 시트로 구성된 파일이며, 시트 목록이 곧 본부 목록이 됩니다. `전사`, `목차`, `안내`, `작성방법`, `상위부서…`, `raw data`, `재물조사대상` 류의 안내성 시트는 기본으로 감춰집니다.
3. 본부 줄에서 `ERP 업로드`를 열고 **② 본부별 ERP 자산 현황 : 엑셀** 을 첨부한 뒤 `데이터셋 등록`을 누릅니다. 서버가 두 파일을 자산번호로 병합해 **본부별 dataset**을 만듭니다.
4. 해당 줄에 자산 건수와 등록일이 뜨면 준비 완료입니다. 같은 본부로 다시 등록하면 덮어씁니다.

> 3단계를 마쳐야 그 본부가 폰의 **소속 선택 목록**에 나타납니다. 전사 양식만 올린 상태로는 본부 목록만 잡히고 데이터셋은 아직 없습니다.
>
> 전사 양식은 서버에 파일째 보관되므로 **화면을 새로고침하거나 서버가 재시작해도 첨부 상태가 유지**됩니다. 예전에는 브라우저 메모리와 서버 임시 캐시(2시간)에만 있어서 새로고침하면 "미첨부"로 돌아갔습니다.

### B. 폰에 앱 설치

1. 관리자 화면 **`기기 관리` 탭의 설치 QR**을 폰으로 찍거나, 안내된 주소를 직접 엽니다.
2. Android는 Chrome 메뉴(⋮) → **홈 화면에 추가**, iPhone은 Safari 공유(□↑) → **홈 화면에 추가**.
   관리자 화면(기기 관리)의 QR과 사용자 화면(조사목록)의 QR은 **같은 주소**를 가리킵니다 — 둘 다 `inventoryInstallUrl()` 한 곳에서 계산합니다.
3. 사내망 밖에서 접속할 때는 PC에서 [`start-ngrok-tunnel.ps1`](../../start-ngrok-tunnel.ps1)로 터널을 열어야 합니다. **ngrok 무료 플랜은 재시작할 때마다 주소가 바뀌므로**, 주소가 바뀌면 홈 화면 아이콘을 지우고 새 주소로 다시 추가해야 합니다.

### C. 현장 조사

1. 앱을 처음 열면 **이름**을 입력하고, **소속(본부)** 을 고릅니다. 소속은 자유 입력이 아니라 **운영관리부에서 배부된 탭 목록에서 선택**합니다. 부서는 선택 입력입니다.
2. `조사 목록` 탭에서 **`새 조사`** → **카테고리명**(예: `2026년 정기재물조사`), **자산 목록(마스터)**, **조사 부서**를 넣고 `조사 시작`.
3. **ERP 자산현황은 자동으로 불러옵니다.** 관리자가 설정 탭에서 그 본부의 ERP 파일을 등록해 두면, 세션을 열 때 서버에서 받아 기기에 색인합니다 (`서버 자동` 배지). 조사자가 폰에서 파일을 첨부할 필요가 없습니다. 서버에 없을 때만 `직접 첨부`로 올리면 됩니다.
4. **`QR 스캔`** 으로 자산 라벨을 찍습니다. 자산번호를 손으로 넣어 `조회`해도 됩니다.
5. 조회된 자산의 **자산명·설치장소·부서확인(이상유무)·비고**를 확인·수정하고, 필요하면 사진을 붙인 뒤 저장합니다. 저장 시 **확인자(검수인)·확인자 부서·조사일**이 함께 기록됩니다.
6. **연속 스캔(`연속`) 모드**를 켜면 마스터에서 조회된 자산은 찍는 즉시 `정상`으로 자동 저장됩니다. 마스터에 없는 자산만 수동 입력으로 넘어갑니다.

### D. 산출물 만들기

조사 화면 아래 **`엑셀 내보내기` → `검수 결과 반영`** 영역에서 만듭니다. 두 파일 모두 **서버에 보관되고 기기에도 저장**됩니다.

1. **`검수 반영 ERP 파일`** — 등록해 둔 ERP 원본 파일 **맨 앞에 4열**(`검수완료` / `검수인부서` / `검수인` / `검수날짜`)을 끼워 넣고 조사 결과로 채운 새 파일입니다. 원본 열과 서식은 그대로 유지됩니다.
2. **`운영관리부 양식 첨부`** 로 운영관리부 재물조사 양식을 붙인 뒤 **`설치부서 대조 (노랑/주황)`** 을 누릅니다. 양식의 **설치부서 셀**을 ERP 설치부서와 자산별로 대조해 칠합니다.
   - 🟡 **노란색** — 설치부서가 이전과 같음
   - 🟠 **주황색** — 설치부서가 바뀜 (셀 메모에 `ERP 설치부서: …` 를 남깁니다)
   - 색 없음 — ERP에 없어 대조하지 못한 자산

## 3. 화면과 메뉴얼

### 온보딩 (PWA 최초 실행)

| 요소 | 동작 |
|---|---|
| 이름 | 검수인 이름. 조사 결과의 `확인자`로 들어갑니다. 필수. |
| 소속(본부) | **운영관리부 배부 탭 중 선택.** 배부된 본부가 하나뿐이면 자동 선택됩니다. 필수. |
| 목록 새로고침 | 서버에서 배부 본부 목록을 다시 받아옵니다. 관리자가 방금 등록했다면 이걸 누르세요. |
| 부서 | 선택 입력. 결과의 `확인자 부서` 뒤에 붙습니다. |

배부된 본부가 아직 하나도 없으면 직접 입력란으로 바뀝니다. 오프라인이면 마지막으로 받아둔 목록이 쓰이고 `오프라인` 안내가 뜹니다.

| 연속 / 연속ON | 연속 스캔 모드. 마스터 조회 자산을 찍는 즉시 `정상`으로 저장하고 스캐너를 다시 엽니다. |

| ERP 자산현황 (☁ / 직접 첨부 / ✕) | 관리자가 등록한 본부 ERP 원본을 서버에서 자동으로 받아옵니다. ☁ 버튼으로 다시 받고, 필요하면 `직접 첨부`로 덮어씁니다. 받은 파일은 기기 IndexedDB에만 저장됩니다. |
| 조회됨 / 마스터 미조회 / 마스터 미조회 · ERP 자동 입력 | 자산번호가 어디서 조회됐는지 알려주는 배지. |

| 자산스티커 미부착 | 체크 시 결과에 함께 기록됩니다. |

| 본부별 결과 엑셀 / 전체 내보내기 | 기존 조사 결과 엑셀 내보내기. |
| (조사목록 상단) 본부별 조사 진행 현황 | 본부별 진행률과 미확인 건수. `미확인 자산 상세 보기`로 자산번호·자산명·모델/규격·설치부서·설치장소·관리부서·취득일자 표를 펼칩니다. |
| 검수 반영 ERP 파일 | 위 D-1 산출물. ERP 파일 등록이 선행돼야 활성화됩니다. |
| 운영관리부 양식 첨부 + 설치부서 대조 | 위 D-2 산출물. |
| 전사 파일에 병합 저장 *(관리자)* | 운영관리부 전체 양식에 이 본부 결과를 병합해 내려받습니다. |

### 설정 탭 → DB 파일 관리 *(관리자)*

| 요소 | 동작 |
|---|---|
| ① 운영관리부 전사 자산 현황 : 엑셀 | 전사 양식을 서버에 영속 보관합니다. `교체`로 새 파일을 올리고, ✕로 삭제합니다. (등록된 본부 데이터셋은 그대로 남습니다) |
| ② 본부별 ERP 자산 현황 : 엑셀 | 본부 줄의 `ERP 업로드`를 열어 파일을 붙이고 `데이터셋 등록`을 누릅니다. 이미 등록된 본부는 `덮어쓰기 등록`이 됩니다. |
| 본부 줄의 🗑 | 그 본부 데이터셋을 삭제합니다. 사용 중인 조사 세션이 있으면 건수를 알리고 한 번 더 확인합니다. |
| ERP 원본 보관 상태 | `ERP 업로드`를 펼치면 현장 앱 자동 로드용 원본이 서버에 있는지 표시됩니다. 없으면 ERP 파일을 한 번 다시 올리면 됩니다. |
| 요약 카드 | 본부 시트 수 / 데이터셋 등록 수 / 전사 양식 첨부 여부 — 모두 **서버 상태** 기준이라 다른 PC에서 열어도 같습니다. |
| 현재 양식에 없는 데이터셋 | 이전 양식으로 등록돼 지금 시트 목록에 없는 데이터셋입니다. 여기서 삭제할 수 있습니다. |

### 통계 탭 *(전체 사용자)*

조사 "건수"가 아니라 **데이터셋의 전체 자산을 분모**로 삼아 100% 조사됐는지 보여줍니다. 관리자가 아니어도 볼 수 있습니다.

| 영역 | 내용 |
|---|---|
| 요약 카드 | 전체 자산 / 확인 완료 / 미확인 / 이상 |
| 전체 진행률 | 100%가 되면 `전 자산 조사 완료 (100%)` 로 바뀝니다. |
| 본부(데이터셋) | 펼치면 설치부서 목록. 전체 건수·확인·미확인·진행률 표시. |
| └ 설치부서 | 펼치면 **확인자별 확인 개수**와 **그 부서의 미확인 자산 상세 표**가 나옵니다. |
| └ └ 확인자 | 확인자 이름·소속 부서·확인 건수·이상 건수 |
| 통계 내보내기 | 본부/부서/확인자 3계층을 한 시트에, 조사 세션 요약을 다른 시트에 담은 xlsx |

`마스터 밖` 은 데이터셋에 없는 자산번호로 저장된 조사 결과 수입니다. `(설치부서 없음)` 은 운영관리부 양식에만 있고 ERP 파일에 없어 설치부서를 알 수 없는 자산입니다.

### 데이터셋 탭 *(확인 전용)*

등록·삭제 기능은 없습니다. 현재 상태와 현장에서 올라온 산출물을 확인·다운로드합니다.

| 영역 | 내용 |
|---|---|
| 자산 데이터셋 | 등록된 본부별 데이터셋의 자산 건수·등록일. 앱에 하드코딩된 번들 데이터셋은 `앱 내장`으로 표시됩니다. |
| 부서별 자산 현황 파일 (검수 반영) | 현장에서 만든, 맨 앞 4열에 검수 정보가 들어간 본부별 ERP 파일 목록. 줄마다 `내려받기`. |
| 운영관리부 전사 파일 (설치부서 대조) | 설치부서를 노랑/주황으로 칠한 운영관리부 양식 목록. 줄마다 `내려받기`. |

### 자산번호 매칭 규칙

자산 라벨 QR은 자산번호를 **하이픈 없이** 내보내는데(`QQ000120240000`) ERP·마스터 데이터에는 하이픈이 들어 있습니다(`QQ00012-0240-000`). 그래서 조회할 때 **두 단계**로 찾습니다.

1. **정확 일치** — 앞뒤 공백을 없애고 대문자로 맞춘 값 그대로 비교
2. **하이픈 무시** — 영문자와 숫자만 남긴 값으로 비교 (`looseAssetKey`)

대소문자·공백·하이픈이 어떻게 섞여 있어도 같은 자산으로 찾습니다. ERP 파일은 **구자산번호로도** 색인하므로, 라벨에 구번호가 찍힌 자산도 조회됩니다.

## 4. 데이터와 저장 위치

| 데이터 | 저장 위치 | 비고 |
|---|---|---|
| 사용자 프로필(이름/소속/부서) | 브라우저 localStorage | 기기별. `변경`으로 초기화 |
| 배부 본부 목록 | localStorage 캐시 + 서버 | 원본은 서버 dataset의 `parentDept` |
| 운영관리부 전사 양식(원본 파일) | 서버 `inventory_survey_forms` + `server/uploads/inventory-survey/` | 새로고침·서버 재시작 후에도 유지 |
| 본부별 마스터 자산 | 서버 SQLite `inventory_datasets` + 기기 IndexedDB 캐시 | 오프라인 대비 캐시 |
| 조사 세션·결과 | 기기 IndexedDB + 서버 `inventory_sessions` | 오프라인 시 큐에 쌓였다가 자동 동기화 |
| 현물 사진 | 기기 IndexedDB | 서버로 전송하지 않음 |
| 본부별 ERP 자산현황 원본 | 서버 `inventory_erp_files` + `server/uploads/inventory-erp/` | 본부당 최신 1개. 현장 앱이 자동으로 받아감 |
| 기기의 ERP 색인 | 기기 IndexedDB `erp_assets` | 서버 원본을 받아 색인한 사본 (또는 직접 첨부한 파일) |
| 검수 반영 ERP / 설치부서 대조 파일 | 서버 `inventory_files` + `server/uploads/inventory/` | 기기에도 Save As |

설정 화면의 상태는 전부 서버에서 읽습니다. 폰의 소속 선택지도 같은 서버 dataset(`parentDept`)에서 나오므로, 관리자가 등록하면 폰에서 `목록 새로고침`만 눌러도 반영됩니다.

## 5. 제약과 알려진 한계

- **ngrok 무료 플랜은 재시작마다 공개 주소가 바뀝니다.** 폰에 저장된 옛 주소는 `ERR_NGROK_3200`으로 죽습니다. 고정 주소가 필요하면 유료 도메인이나 사내 고정 IP 접속으로 바꿔야 합니다.
- **터널 경유 시 HMR 웹소켓이 연결되지 않습니다.** 중계 미들웨어가 업그레이드 요청을 처리하지 않기 때문입니다. 화면 동작에는 영향이 없지만 코드를 고치면 폰에서 수동 새로고침이 필요합니다.
- 서버 병합은 ERP 설치부서와 운영관리부 설치부서를 **하나의 `dept`로 합칩니다**(ERP 우선). 그래서 설치부서 대조는 서버 dataset이 아니라 **원본 파일 두 개**로 해야 합니다 — 앱이 ERP 파일과 운영관리부 양식을 각각 요구하는 이유입니다.
- 셀 배경색은 SheetJS 커뮤니티 버전이 쓰지 못하므로 산출물 생성에만 `exceljs`를 씁니다.
- 하이픈 무시 키가 서로 다른 두 자산에서 겹치면 **먼저 색인된 자산**이 남습니다. 정확 일치가 항상 우선하므로 정상적인 자산번호 체계에서는 문제가 되지 않습니다.
- 산출물 파일은 서버에 보관만 되고 **삭제 UI가 아직 없습니다.**
- 통계의 부서 구분은 **자산의 설치부서**입니다. 운영관리부 양식에만 있고 ERP에 없는 자산은 설치부서가 비어 `(설치부서 없음)` 으로 모입니다. (현재 융합기술본부 9,291건 중 2,735건)
- 커버리지 통계는 요청할 때마다 데이터셋 전체를 파싱합니다. 자산이 수십만 건 규모로 커지면 캐시가 필요합니다.
- **이 기능(2026-08-24) 이전에 등록된 데이터셋은 ERP 원본이 서버에 없습니다.** 설정 탭에서 그 본부의 ERP 파일을 한 번 다시 올리면 이후로는 현장 앱이 자동으로 받아 씁니다.
- 설치 주소는 `VITE_INVENTORY_APP_URL`에서 옵니다. Vite는 `.env.[mode]`를 `.env.local`보다 **우선** 적용하므로, 이 변수를 `.env.admin` 같은 모드 파일에 두면 ngrok 스크립트가 갱신한 최신 주소를 그 모드만 못 쓰게 됩니다. `.env.local`에만 두세요.
- **데이터셋 삭제는 되돌릴 수 없습니다.** 조사 세션이 남아 있을 때만 경고하므로, 세션을 먼저 지운 뒤 삭제하면 확인창 한 번으로 수만 건이 사라집니다. 삭제 전 `데이터셋 탭 → 본부별 자산현황 엑셀 다운로드`로 백업을 받아두세요.
- 삭제 직후라면 SQLite가 VACUUM 하기 전이므로 `server/data/aihub.db` 를 즉시 복사해 두면 카빙으로 대부분 복구할 수 있습니다. (2026-08-23에 9,291건 중 9,258건 복구한 전례)
