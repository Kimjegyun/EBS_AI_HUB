# 시연 영상 시나리오 — EBS AI HUB

**목표 길이 4분 35초** (심사 영상은 3~5분이 표준. 5분을 넘기면 끝까지 안 봅니다)
**촬영 구성**: PC 화면 녹화 + 폰 화면 녹화 두 소스를 편집으로 합침

---

## 0. 영상의 전략 — 무엇을 보여줄 것인가

심사위원이 영상에서 확인하려는 것은 딱 세 가지입니다.

1. **진짜 문제인가** — 만든 사람이 지어낸 문제가 아닌가
2. **진짜 동작하는가** — 슬라이드가 아니라 실물이 도는가
3. **왜 이게 어려운가** — 아무나 할 수 있는 것이면 점수가 안 됩니다

그래서 이 영상의 뼈대는 **"문제 → 실물 시연 → 어려웠던 지점"** 입니다.
기능을 나열하지 말고 **하나의 자산이 QR에서 엑셀까지 흘러가는 과정**을 끝까지 따라가세요.
그게 가장 강력합니다.

> ❌ 하지 말 것: 코드 에디터 스크롤, 아키텍처 다이어그램 오래 띄우기, 기능 목록 읽기
> ✅ 할 것: 실제 장비에 붙은 라벨을 폰으로 찍는 장면, 비행기 모드, 엑셀 셀 색깔

## 1. 구간별 시나리오

### 【0:00 – 0:25】 문제 제시 — 실물로 시작

**화면**: 실제 방송장비(카메라·조명기 등)에 붙은 **자산 라벨 클로즈업**.
라벨의 자산번호 `QQ00012-0240-000`이 보이게.

**내레이션**
> "정기 재물조사는 이 라벨 하나하나를 엑셀 대장과 눈으로 대조하는 일입니다.
> 방송장비만 9,291건. 그런데 문제가 있습니다."

**화면 전환**: 화면 반으로 분할해 텍스트 대비
```
    QR이 내보내는 값      →   QQ000120240000
    ERP 대장의 값         →   QQ00012-0240-000
```
빨간색으로 하이픈 위치를 강조.

**내레이션**
> "QR은 하이픈 없이, 대장은 하이픈을 넣어 기록합니다.
> 같은 자산인데 시스템은 다른 자산으로 봅니다."

> 💡 **이 25초가 영상 전체에서 가장 중요합니다.** 심사위원이 "아, 진짜 현장 문제구나"를
> 느끼는 구간입니다. 라벨 실물 촬영을 반드시 넣으세요. 스크린샷으로 대체하지 마세요.

### 【0:25 – 1:05】 관리자 준비 — 엑셀 두 개를 넣으면 끝

**화면**: PC 브라우저, 관리자 화면 → 설정 → DB 파일 관리

**동작 순서** (녹화 시 이대로)
1. `운영관리부 전사 자산 현황` 드롭존에 엑셀을 **드래그해서 놓는다**
2. 시트 목록이 뜨면서 본부 목록이 잡히는 것을 보여준다
3. `융합기술본부` 줄을 펼치고 `ERP 자산현황` 파일을 첨부
4. `데이터셋 등록` 클릭 → **결과 메시지가 뜨는 순간 정지**
   `융합기술본부 등록 완료 — 총 9,291건 (병합 8,800 · 양식만 120 · ERP만 371)`

**내레이션**
> "관리자가 하는 일은 엑셀 두 개를 올리는 것뿐입니다.
> 운영관리부가 배부한 전사 양식, 그리고 본부별 ERP 자산현황.
> 서버가 자산번호로 두 파일을 병합해 9,291건의 마스터를 만듭니다."

> 💡 **팁**: 병합 결과의 `병합 / 양식만 / ERP만` 숫자를 잠깐 확대하세요.
> "두 파일을 그냥 합친 게 아니라 대조했다"는 것이 이 숫자로 증명됩니다.

### 【1:05 – 1:35】 현장 설치 — QR 한 번으로

**화면**: PC의 설치 QR → **폰 카메라로 실제로 찍는 장면** (손이 나오게)
→ 폰 화면으로 전환 → "홈 화면에 추가" → 앱 아이콘 생성 → 실행

**동작**: 온보딩에서 **이름 입력** → **소속(본부) 칩을 탭해서 선택**

**내레이션**
> "현장 담당자는 앱스토어에 갈 필요가 없습니다. QR 한 번으로 폰에 설치됩니다.
> 소속은 직접 입력하지 않습니다. 운영관리부가 배부한 본부 목록에서 고릅니다.
> 오타로 부서명이 갈라지는 일이 없습니다."

> 💡 소속을 "타이핑하지 않고 탭해서 고르는" 장면을 분명히 보여주세요.
> 사소해 보이지만 **집계가 깨지지 않는 이유**라서 뒤의 통계 장면과 연결됩니다.

### 【1:35 – 2:20】 ⭐ 핵심 — QR 스캔이 하이픈을 넘는다

**화면**: 폰 화면 녹화 + 장비 라벨을 비추는 손

**동작 순서**
1. `QR 스캔` 탭
2. 카메라가 라벨을 잡는 순간
3. **자산 정보가 자동으로 채워지는 화면을 3초간 정지**
   - 자산명 `LED 조명기`, 설치장소, 설치부서, 취득일자가 채워진 상태
4. 화면 위에 자막 오버레이:
   `QR: QQ000120240000  →  매칭: QQ00012-0240-000  ✅`

**내레이션**
> "스캔하면 바로 조회됩니다.
> 하이픈이 없는 QR 값과 하이픈이 있는 대장 값을, 영숫자만 남긴 보조 키로 한 번 더 대조합니다.
> 정확히 일치하면 그것을 쓰고, 아니면 하이픈을 무시하고 찾습니다.
> 기존에 저장된 조사 결과의 키는 건드리지 않기 때문에 과거 데이터도 그대로 조회됩니다."

5. **연속 스캔 모드 ON** → 라벨 3~4개를 **빠르게 연속으로 찍는다**
   → 찍을 때마다 `✓ 저장` 토스트가 뜨는 장면

**내레이션**
> "연속 모드에서는 찍는 즉시 정상 처리로 저장되고 스캐너가 다시 열립니다.
> 수백 건을 처리해야 하는 현장에서 탭 수를 줄이는 것이 곧 시간입니다."

> 💡 **이 45초가 영상의 심장입니다.** 여기에 가장 많은 시간을 쓰세요.
> 연속 스캔은 리듬감이 있어서 영상에서 특히 잘 먹힙니다.

### 【2:20 – 2:45】 ⭐ 오프라인 — 비행기 모드로 증명

**화면**: 폰 상단에서 **제어센터를 내려 비행기 모드를 켜는 장면** (아이콘이 켜지는 것 확인)

**동작**
1. 비행기 모드 ON — 상단에 오프라인 배너가 뜨는 것 확인
2. 그 상태로 **QR 2건을 계속 스캔하고 저장**
3. 비행기 모드 OFF
4. 배너가 사라지고 **동기화가 도는 것**을 보여줌

**내레이션**
> "조사 현장은 스튜디오, 부조정실, 기계실입니다. 전파가 닿지 않는 곳이 많습니다.
> 자산 목록과 조사 결과, 사진까지 기기에 저장되기 때문에 통신이 끊겨도 계속 조사합니다.
> 연결이 돌아오면 쌓아둔 결과가 자동으로 서버로 올라갑니다."

> 💡 **비행기 모드 아이콘이 켜지는 순간을 반드시 화면에 담으세요.**
> "오프라인 지원"이라고 말로 하는 것과 눈으로 보는 것은 설득력이 다릅니다.

### 【2:45 – 3:25】 ⭐ 엑셀 산출물 — 색으로 말한다

**화면**: 폰에서 산출물 생성 → PC 엑셀로 전환

**동작 순서**
1. 폰에서 `검수 반영 ERP 파일` 탭 → 생성 완료 토스트
2. PC에서 그 엑셀을 연다 → **맨 앞 4열이 추가된 것을 보여준다**
   `검수완료 | 검수인부서 | 검수인 | 검수날짜`
   → 오른쪽으로 스크롤해 **원래 ERP 열이 그대로 있는 것**을 보여준다
3. 폰에서 `설치부서 대조 (노랑/주황)` 탭
4. PC에서 그 엑셀을 연다 → **설치부서 열의 노란색·주황색 셀**을 보여준다
5. 주황색 셀에 마우스를 올려 **메모 `ERP 설치부서: 제작기술부`** 를 띄운다

**내레이션**
> "결과는 담당자가 쓰던 엑셀 그대로 나옵니다.
> 원래 열과 서식은 하나도 건드리지 않고, 검수 정보 네 개 열만 맨 앞에 끼워 넣습니다.
> 새 양식을 배울 필요가 없습니다.
>
> 운영관리부에 보내는 파일은 설치부서를 대조해서 색으로 표시합니다.
> 노란색은 그대로, 주황색은 부서가 바뀐 자산입니다.
> 셀 메모에 원래 부서가 남아 있어서, 보고받는 사람이 스크롤만 해도 무엇이 바뀌었는지 보입니다."

> 💡 **주황색 셀의 메모를 띄우는 장면을 꼭 넣으세요.** 디테일이 살아있다는 인상을 줍니다.
> 엑셀은 화면을 **150% 이상 확대**해서 녹화해야 색이 잘 보입니다.

## 2. 촬영 체크리스트

### 촬영 전 준비
- [ ] **실제 자산 라벨이 붙은 장비** 3~4대 준비 (연속 스캔용)
- [ ] 데모용 데이터셋을 미리 등록해 두고, 관리자 시연은 **다른 본부**로 새로 등록
- [ ] 조사 결과를 몇 건 미리 넣어둔다 → **통계 화면이 0%가 아니어야 함** ⚠️
- [ ] 설치부서가 **바뀐 자산이 최소 1건** 있는 ERP 파일 준비 (주황색을 보여줘야 함)
- [ ] 폰 배터리·알림 끄기, 방해금지 모드
- [ ] 브라우저 북마크바·확장 아이콘 숨기기, 시크릿 창 권장

### 녹화 설정
- [ ] PC: 1920×1080, 브라우저 확대 110~125% (글자가 작으면 안 보입니다)
- [ ] 폰: 화면 녹화 기능 사용, 세로 촬영 → 편집에서 좌우 여백 처리
- [ ] 엑셀 장면만 150% 이상 확대

### 편집
- [ ] 자막 필수 — 심사는 소리를 끄고 볼 수도 있습니다
- [ ] 파일 업로드·병합 등 **기다리는 구간은 배속 처리**하고 "처리 중" 자막
- [ ] 화면 전환마다 구간 제목 자막 (`① 관리자 준비`, `② 현장 스캔` …)
- [ ] 강조 지점은 확대 + 빨간 테두리

### 절대 화면에 나오면 안 되는 것 ⚠️
- [ ] `.env` 파일, API 키, `VITE_INVENTORY_TOKEN`, ngrok authtoken
- [ ] 실제 직원 이름·계정 (검수인은 "홍길동" 등 가명 사용)
- [ ] 사내 IP 주소, ngrok 실제 주소 (필요하면 모자이크)
- [ ] 실제 자산의 민감 정보 (필요하면 데모용 데이터셋으로 촬영)

## 3. 수상권을 노리는 특장점 — 우선순위

보고서와 영상에서 **이 순서로** 강조하세요. 위에 있을수록 심사에서 힘이 셉니다.

### 1위. 실제로 쓰이는 실무 문제를 풀었다
가상의 시나리오가 아니라 **방송장비 9,291건**이라는 실데이터로 검증했습니다.
대회 출품작 대부분이 "만들어본 것"에 머무는데, 이건 "쓰이는 것"입니다.
→ **숫자를 반복해서 노출하세요.** 9,291건, 40개 부서, 실데이터.

### 2위. 남들이 안 보는 곳에서 문제를 찾았다 — 하이픈
"자산번호가 일치하지 않는다"는 알고리즘 문제가 아니라 **데이터 표기 문제**입니다.
데이터를 직접 열어본 사람만 발견할 수 있습니다.
→ 심사위원이 "현장을 아는 팀"이라고 판단하게 만드는 결정적 포인트입니다.
→ 게다가 **기존 저장 키를 깨뜨리지 않는 방식**(보조 색인)을 택한 것은 설계 성숙도를 보여줍니다.

### 3위. 오프라인 우선 설계
말로 하는 오프라인 지원은 흔하지만 **비행기 모드로 증명하는** 영상은 드뭅니다.
IndexedDB + 동기화 큐 + Service Worker를 실제로 조합했습니다.
→ 영상에서 반드시 실연하세요.

### 4위. 엑셀을 버리지 않고 감쌌다
업무 전산화가 실패하는 이유는 담당자에게 새 양식을 강요하기 때문입니다.
**원본 열과 서식을 보존하고 필요한 열만 앞에 덧붙이는** 접근은
"현업을 이해한 설계"라는 인상을 줍니다.
→ 엑셀 오른쪽 스크롤로 "원래 열이 그대로 있다"를 보여주는 게 핵심.

### 5위. 색으로 말하는 산출물
노랑/주황 셀 + 셀 메모. **SheetJS 커뮤니티 버전이 셀 채우기를 못 써서
이 산출물만 exceljs로 처리했다**는 기술적 판단까지 곁들이면 깊이가 드러납니다.

### 6위. 집계의 분모를 바꿨다
"몇 건 했나" → "전체 중 몇 %". 단순한 변경이지만 **관리자가 실제로 묻는 질문**에
처음 답할 수 있게 됐다는 서술이 설득력 있습니다.

### 7위. 플러그인 허브 구조
파일 하나 + 레지스트리 한 줄로 앱 추가. **오픈소스로서 남이 확장할 수 있는 구조**라는
점을 강조하면 대회 취지(오픈소스)와 맞물립니다.

### 8위. 라이선스 청결
직접 의존성 60개 전부 MIT/Apache-2.0/BSD. **카피레프트 0건.**
→ 오픈소스 대회에서 이건 은근히 큰 가점입니다. 보고서에 한 줄 명시하세요.

### 9위. 문서를 코드와 함께 관리
앱마다 실행 순서·메뉴얼·저장 위치·알려진 한계 문서를 두고 기능 변경 시 함께 갱신.
**"공개했을 때 남이 이어받을 수 있는 상태"** 라는 오픈소스 성숙도 지표입니다.

## 4. 솔직하게 말하면 더 점수가 되는 것

심사위원은 **한계를 아는 팀**을 높이 봅니다. 약점을 숨기지 말고 로드맵과 함께 제시하세요.

- **데이터 삭제 사고와 복구 경험**
  개발 중 9천여 건 데이터셋이 확인창 한 번으로 삭제됐고, SQLite가 삭제 직후에는
  페이지를 재사용하지 않는 점을 이용해 오버플로 페이지 체인을 되짚어 **99.6%를 복구**했습니다.
  → 이건 약점이 아니라 **문제 해결력을 보여주는 일화**입니다.
    "그래서 휴지통과 복원 API를 로드맵 1순위로 뒀다"로 마무리하면 완성됩니다.
  → 소감란에 넣는 것을 권합니다. 영상에는 넣지 마세요(시간이 아깝습니다).

- **현장 PWA의 공유 토큰 인증** — 기기별 인증이 필요하다는 것을 알고 있다
- **터널 주소 변동** — 고정 도메인 배포가 다음 단계
- **통계 캐시 부재** — 수십만 건 규모에서 필요
